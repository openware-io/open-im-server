# Pre-existing non-ASCII .ps1 files deferred out of validate-powershell-ascii-only.ps1.
#
# This is a DEFERRAL list, not an exemption list. Each entry names the batch that clears it.
# Counts are non-ASCII BYTES (what the gate reports), not characters.
#
# EMPTY as of batch 4: every scripts/**/*.ps1 is now ASCII-only, so the gate is fully blocking
# with no deferrals. The file is kept so the mechanism and its rules stay documented.
#
# Rules for this file:
#   - one entry per line:  <repo-relative-path> | <clearing batch> | <reason>
#   - a file may only be listed while its worklist has a finite, enumerated set of items;
#   - when a file becomes ASCII-only the entry is DELETED: a stale entry is itself a gate failure;
#   - entries are never added back after removal, and new files are never added.
#
# Two claims that used to be in this header were measured and found false, and are corrected here
# so they do not get repeated:
#
#   - Not every offender was BOM-less "since the initial commit" as a deferral: `scripts/verify/
#     verify-a380-ktv-closure.ps1` had a Chinese room-type name in an SQL literal that is only ever
#     used as an id, so no assertion depended on it; and four `.ps1` files in `scripts/verify/`
#     already declared "must be ASCII-only" in their own headers. The N-20 record in
#     docs/renovation/ENGINEERING_GOVERNANCE_03_REMEDIATION.md describes it as an identified
#     residual hazard, not as content to preserve.
#   - Chinese comments in a BOM-less .ps1 are NOT mis-decoded into parse failures by Windows
#     PowerShell 5.1. Measured with the 5.1 executable that this repository actually uses
#     (%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe): all 60 scripts under
#     scripts/ parse with zero errors both before and after the batch-4 translation, and a
#     BOM-less .ps1 containing a Chinese comment executes correctly. The real hazard the gate
#     guards is a non-ASCII byte inside a regex or string literal being decoded as ANSI, which
#     silently changes matching; that is why the rule stays ASCII-only rather than "BOM required".
#
# Empty lines and lines starting with '#' are ignored.
