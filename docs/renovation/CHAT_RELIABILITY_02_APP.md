## 方案信息

- 方案集：`CHAT_RELIABILITY`
- 顺序号：`02`
- 实施边界：Flutter App 的消息同步、群资料、WebSocket 事件和极光通知处理
- 前置方案：[服务端改造说明](CHAT_RELIABILITY_01_SERVICE.md)
- 关联契约：[消息 OpenAPI 快照](../contracts/openapi/message.json)、[会话 OpenAPI 快照](../contracts/openapi/conversation.json)

## 消息同步约定

1. 将每个登录用户的最大 `syncSeq` 持久化到本地；切换账号时必须隔离该水位和本地消息。
2. 应用启动、登录成功、WebSocket 重连、从极光通知进入会话以及检测到实时序号缺口时，分页请求 `/messages/sync`，直到 `hasMore=false`。
3. 先按 `msgId` 幂等写入本地消息，再把同步水位更新为服务端 `nextSyncSeq`。旧请求返回时不得将水位或消息状态回退。
4. 使用同步条目的 `readAt` 标记当前用户已读；`readAt` 为空则保留未读。不要把消息全局 `status` 当作当前用户的已读状态。
5. WebSocket `chat:receive` 和撤回/成员变更事件只用于加速展示；断线期间或通知唤醒后的完整性始终由 HTTP 同步保证。

## 群聊界面约定

- 群详情和成员列表仅向当前群成员展示；用户主动退群、被移除或群解散后，清除该群本地会话入口并停止继续同步该群消息。
- `GET /groups/{id}/members` 的成员项包含 `username` 和 `avatar`。收到成员变化事件或打开群资料页时刷新成员列表，更新头像、用户名和角色。
- 只有群主可调整管理员角色；群主离群后以服务端返回的新群主为准，不在客户端自行推算继任者。
- 普通成员邀请由服务端 `allowMemberInvite` 决定，客户端可以展示入口，但必须处理服务端拒绝；不得仅依赖本地角色判断权限。

## 极光通知约定

- 通知只表示“可能有新消息”，不能直接生成聊天记录；收到通知后进入对应会话或恢复应用时执行同步。
- 通知正文可能是通用文案，App 必须依赖会话标识和消息同步获取真实内容。
- iOS 正式包使用生产 APNs，与 ACK 的 `JPUSH_APNS_PRODUCTION=true` 保持一致；测试包和测试环境必须使用独立的极光/证书配置，不能覆盖 ACK 正式 Secret。

## 验收场景

1. App 离线期间收到私聊和群消息，重新上线后历史记录完整且无重复。
2. 新安装设备同步历史后，已读消息不重新计入未读。
3. 退群后不再获得该群新消息；被踢、群解散和群主转让均刷新群信息。
4. 群成员改头像或用户名后，刷新成员列表可显示新资料。
5. 离线 Push 失败或用户关闭通知权限时，消息仍可在下次同步中恢复。
