# IM 用户注销与管理员删除规范

## 业务原则

1. 用户主动注销是软删除：`user_account` 保留，状态为“注销/disabled”，注销申请与注销日志保留；所有 IM 业务查询、列表、搜索、登录和会话展示均不得再显示该用户。
2. 管理员在 IM 后台删除用户是硬删除：`user_account` 及该用户在 IM 业务域内的全部业务数据物理删除，不保留 `deleted_*` 墓碑账号，不通过墓碑判断删除状态。
3. 两种删除都必须清理 IM 业务域数据及缓存：用户资料关联、设备/会话、好友关系、群/频道成员、密聊、消息、消息索引、已读状态、收藏、同步序列、Redis 缓存和本地投影。
4. 删除任务必须幂等、可重试，并通过 Outbox/MQ 记录跨 IM 服务的清理进度；消息序号允许断号。
5. 审计日志、注销申请日志和删除任务日志属于合规证据，不得被用户级联删除。
6. SaaS 身份、客户档案、订单、支付、租户等非 IM 业务数据不得由 IM 删除流程物理删除；IM 只解除自身绑定并记录结果。

## 数据库原则

- 数据库不建立物理外键；服务边界通过应用层删除顺序、幂等事件和补偿机制维护一致性。
- 迁移必须使用 Flyway，历史迁移不可改写；危险 DDL/DML 必须新增版本并提供影响评估与回滚/备份方案。
- 每个表必须登记所属业务域；跨域表只能通过明确的服务 API 或事件访问。
- 审计表仅追加/归档，不参与业务删除级联。

## 删除差异

| 场景 | 用户主记录 | IM 业务数据 | 审计/注销日志 | SaaS 关联 |
|---|---|---|---|---|
| 用户主动注销 | 保留，状态注销 | 清理并隐藏，不再展示 | 保留 | 不删除，仅解除 IM 绑定/记录结果 |
| 管理员后台删除 | 物理删除 | 全量物理删除 | 保留 | 不删除，仅解除 IM 绑定/记录结果 |

## 发布验收

删除策略、数据库迁移、缓存清理、事件消费者和前后端契约变更必须一起通过全量规范检查、全量构建、Kind digest 发布核对和浏览器回归测试后才允许发布。
