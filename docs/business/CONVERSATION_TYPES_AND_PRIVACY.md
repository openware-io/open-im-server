# 会话空间与隐私边界（产品业务文档）

> 文档定位：gv_chat 的**产品业务文档**，沉淀"四类会话空间 + 消息生命周期 + 隐私边界"的需求语义。需求来源为 Telegram 类 IM 原型规格（PRD + 高保真原型），本文件是其在工程内的权威落点；实现细节见 [频道域设计](../features/CHANNEL_01_SERVICE.md) 与 [私密聊天与 E2EE 设计](../features/SECRET_CHAT_01_E2EE.md)。

## 1. 核心产品原则

1. **传输加密 ≠ 端到端加密（E2EE）**：不能以一句"消息已加密"模糊描述。云端会话应明确"服务端可访问内容"，只有私密聊天才可宣称 E2EE。
2. **删除 / 撤回 = 一次同步删除动作**：不能承诺"撤销对方已保存的副本"（截图、转发、下载、本地保存不可控）。删除语义是"服务端记录与对方设备上的这条消息同步移除"，已阅读/复制的本地内容无法撤回。

## 2. 四类会话空间（信息架构）

| 会话 | 定位 | 关键能力 | 隐私边界 |
|------|------|---------|---------|
| 云端单聊（private） | 日常多端沟通 | 消息 / 回复 / 转发 / 编辑 / 双方删除、跨设备历史同步 | 服务端明文托管 |
| 云端群组（group） | 多人协作与治理 | 成员 / 角色 / 禁言 / 移除 / 提升、邀请链接、公告、置顶、话题、审计事件 | 服务端明文托管 |
| 频道（channel） | 单向广播 | 所有者（owner）发布，订阅者阅读；通知 / 分享；可关联讨论组 | 服务端明文托管，仅 owner 可发布 |
| 私密聊天（secret，仅 1v1） | 高敏感一对一 | E2EE、安全码 / 指纹核验、定时销毁、不同步到新设备 | 服务端仅转存密文，不可解密 |

## 3. 消息生命周期

```
草稿 → 客户端提交 → 发送中 → 服务端对端确认 → 已送达 → 已读
                    └─────────── 失败 / 重试
发送后：回复 / 转发 / 编辑 / 反应 / 置顶 / 删除
```

- **云端会话**：服务端保存并分发，新设备可同步历史。
- **私密聊天**：两设备协商密钥，服务端仅转存密文；新设备无历史无密钥；定时销毁建议按"已读后计时"。

## 4. 删除与撤回语义

- **撤回**：发送者在窗口期内撤回，服务端以 tombstone 保留同步游标（不物理删除导致客户端游标断裂），通过 MQ/WebSocket 实时通知双方。
- **删除（双方同步删除）**：云端单聊/群组提供"为所有人删除"能力——服务端移除记录，并同步移除对方设备上的这条消息；已阅读/复制的本地内容无法撤销（边界文案明确告知）。

## 5. 隐私边界规则

- 云端会话：服务端可访问内容（明文），多端同步。
- 私密聊天：
  - 服务端仅存储密文与元数据（发送者、序号、状态、销毁时间），不解密。
  - 新设备不自动同步历史与密钥（需恢复流程）。
  - 定时销毁：消息被对方已读后开始计时，到期后服务端标记销毁，双方设备同步移除（不同步到新设备）。

| 能力 | 实现状态 |

| 定时销毁引擎（已读后计时 + 周期扫描） | ✅ 已实现并部署（详见 [私密聊天与 E2EE 设计](../features/SECRET_CHAT_01_E2EE.md)） |

| 编辑 / 反应 / 置顶 / 邀请链接 / 话题 / 审计事件 | 📋 需求范围内，待排期 |

## 7. 边界与不承诺

- 不承诺撤销对方已保存的本地副本（截图/转发/下载/本地保存不可控）。
- 云端会话不宣称 E2EE；只有私密聊天可宣称端到端加密。
