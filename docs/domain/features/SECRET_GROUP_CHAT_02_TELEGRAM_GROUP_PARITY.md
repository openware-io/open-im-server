# 私密群聊 · Telegram 群组（Group）语义对齐（SECRET_GROUP_CHAT_02）

> 文档定位：本产品四类会话的映射与「私密群聊」对齐 Telegram 群组（Group）的能力清单。
>
> **产品映射（权威）**：
> | 本产品 | 对应业务 |
> |---|---|
> | 普通单聊 | 微信单聊 |
> | 普通群聊 | 微信群聊 |
> | 私密聊天（1v1） | Telegram 秘密聊天 Secret Chat（E2EE） |
> | **私密群聊** | **Telegram 群组 Group** |
>
> 四类会话彼此独立，互不混用。私密群聊在**逐成员 E2EE（隐私底座）**之上，补齐 Telegram 群组的管理能力；普通群聊保持微信群聊的简单形态。

## 1. Telegram 群组业务能力清单

| 分组 | 能力 | 说明 |
|---|---|---|
| 群形态 | 私密群 / 公开群 | 私密群仅邀请链接可入；公开群可搜索/链接加入 |
| 成员治理 | 群主 + 多管理员 + 成员 | 角色分级 |
| 成员治理 | 精细管理员权限（分项） | 改群信息 / 删消息 / 禁言封禁 / 邀请 / 置顶 / 匿名管理等逐项开关 |
| 成员治理 | 精细成员权限（分项） | 发消息 / 发媒体 / 发贴纸 / 发投票 / 发链接 / 邀请等逐项开关 |
| 成员治理 | 禁言 / 封禁 / 移除 / 管理员头衔 | 成员处置与自定义头衔 |
| 消息 | 删除消息所有人（无限时） | 无 2 分钟限制，服务端协调全员移除 |
| 消息 | 撤回 | 服务端同步撤回 |
| 消息 | 编辑消息 | 已发消息可编辑 |
| 消息 | 置顶 / 公告 | pin + 全员通知 |
| 消息 | 话题（topics） | 超级群内分话题 |
| 消息 | 慢速模式 | 发言限频 |
| 隐私 | 匿名发言 | 发送者身份隐藏为群名 |
| 邀请 | 邀请链接 | 人数上限 / 有效期 / 撤销；群二维码 |

## 2. 对照与缺口

| Telegram 群组能力 | 私密群聊现状 | 缺口 | 优先级 |
|---|---|---|---|
| 逐成员 E2EE（隐私底座） | ✅ 已实现 | 无 | - |
| 删除消息所有人（服务端协调） | ⚠️ 后端已写、客户端未接 | 接客户端 | P0 |
| 撤回（服务端同步） | ⚠️ 后端已写、客户端未接 | 接客户端 | P0 |
| 阅后即焚（既有私密能力） | ⚠️ 后端引擎已写、客户端未接 | 接客户端 markRead/同步 | P0 |
| 编辑消息 | ❌ | 后端 + 客户端 | P1 |
| 匿名发言 | ❌ | 后端 + 客户端 | P1 |
| 精细管理员/成员权限（分项） | ❌ 仅群主 | 后端 + 客户端 | P1 |
| 邀请链接（人数/有效期/撤销） | ❌ | 后端 + 客户端 | P1 |
| 置顶 / 公告 | ❌ | 后端 + 客户端 | P2 |
| 话题 / 慢速模式 | ❌ | 后端 + 客户端 | P2 |
| 功能开关 | ⚠️ 已有开关基建、缺新开关 | 后台每能力一个开关 | P0 |

## 3. 功能开关规划（后台「系统配置 → 功能开关」）

| 开关键 | 含义 | 默认 |
|---|---|---|
| `feature.secretGroupChatEnabled` | 私密群聊总开关（已补） | true |
| `feature.groupDeleteEveryoneEnabled` | 删除所有人 / 撤回 | true |
| `feature.groupEditMessageEnabled` | 编辑消息 | true |
| `feature.groupAnonymityEnabled` | 匿名发言 | false |
| `feature.groupInviteLinkEnabled` | 邀请链接 | true |
| `feature.groupPinnedEnabled` | 置顶 / 公告 | true |
| `feature.chatDeleteEnabled` | 聊天删除/撤回/清空总开关（跨各类聊天，粗粒度） | true |

> 说明：功能开关在客户端（`/config/client`）下发之外，已由后端消息服务做**服务端强制校验**（`FeatureTogglePort` → 管理服务 `GET /internal/admin/config/feature-flags`，60s TTL 缓存，拉取失败默认放行）。关闭 `privateChatEnabled`/`groupChatEnabled` 时服务端拒绝存储对应消息；关闭 `chatDeleteEnabled` 时服务端拒绝删除/撤回/清空。

## 4. 执行顺序

1. P0：接客户端——markRead / destroyed-states 同步 / 删除所有人 / 撤回（后端已就绪）。
2. P0：功能开关——补全新开关（迁移 + 后台 UI + `/config/client` + 客户端消费）。
3. P1：编辑消息、匿名发言、精细权限、邀请链接。
4. P2：置顶/公告、话题、慢速模式。
