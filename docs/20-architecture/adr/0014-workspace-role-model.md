# ADR 0014: Platform, tenant and store workspaces and role governance

## Status / 状态

**accepted（已接受，2026-10-23）**。取代 ADR 0013 中“角色档案表作为角色管理来源”的简化实现。

## Context / 背景

现有实现把三个不同主体混在同一套菜单和角色表里：

```text
平台运营（SaaS 厂商）
租户总部（客户企业）
门店经营（客户门店）
```

具体问题：

- 平台和租户共用“租户管理”菜单，语义冲突；
- 平台账号可以看到租户后台，租户账号可以看到平台入口；
- `iam_role_profile` 只描述工作区/落点，不能表达角色权限；
- 角色权限页是占位，租户无法创建自定义角色；
- 门店角色数据范围显示“全部”，没有强制门店边界；
- 平台支持缺少受控代操作边界。

不再兼容该简化模型，按新模型重建。

## Decision / 决策

### 1. 三个工作区，职责硬分离

```text
PLATFORM  平台运营：租户生命周期、套餐/权益、平台角色、审计、运维
TENANT    租户总部：组织/门店、员工/角色、业务开通、账单、报表
STORE     门店经营：前台、订单、收银、资源、库存、门店报表
```

平台角色不能访问租户业务；租户角色不能访问平台功能；门店角色必须绑定具体门店。

### 2. 门店默认独立工作区，可按租户配置

默认门店员工登录进入 `STORE` 工作区。

租户可以配置：

```text
storeWorkspaceMode = INDEPENDENT | TENANT_CONTEXT
```

- `INDEPENDENT`：门店独立工作区，店长看不到租户总部；
- `TENANT_CONTEXT`：门店作为租户后台内的经营上下文，适合小客户统一管理。

两种模式共用同一套门店权限和数据范围，不复制角色。

### 3. 角色分层

```text
平台角色：tenant_id = NULL, scope_level = PLATFORM
租户角色：tenant_id = 租户ID, scope_level = TENANT
门店角色：tenant_id = 租户ID, scope_level = STORE
```

预置角色只读；租户可复制预置角色或创建自定义角色，但只能使用本租户范围内的权限。

平台角色只能由平台管理员创建和维护。

### 4. 权限、范围、权益、工作区分离

```text
Permission   最小授权单位（菜单/动作/API）
Role         权限集合
Scope        平台 / 租户 / 门店
Assignment   账号 + 角色 + 租户/门店
Entitlement  租户开通的业务模块
Workspace    平台 / 租户 / 门店入口
```

最终可见性：

```text
workspace ∩ role permissions ∩ tenant entitlement ∩ context scope
```

后端必须用同一权限码做 API 强制校验；菜单只是投影。

### 5. 临时授权后置

平台支持代操作默认禁止。

后续如需支持，必须：

```text
显式申请
租户 owner 同意（或合同授权）
限时 token
全量审计
到期自动回收
```

本次不实现。

### 6. 角色管理页

角色管理页负责：

```text
角色列表（平台/租户/门店）
创建/复制/停用租户角色
权限矩阵
已分配人员
```

角色工作台默认值（落点、优先级、默认业态）只作为展示配置，不再作为权限来源。

## Invariants / 不变量

- 平台角色不能分配给租户账号；
- 租户角色不能包含 `platform.*` 权限；
- 门店角色必须绑定 `store_id`；
- 租户只能修改本租户自定义角色；
- 预置角色不可原地修改，只能复制；
- 权限授予必须同时满足 `grantable_levels` 和角色 `scope_level`；
- 任何菜单可见性都必须有服务端 API 权限兜底；
- 任何数据查询都必须带租户/门店范围，不依赖前端隐藏。

## Consequences / 影响

- 删除 `iam_role_profile` 作为权限来源；
- 平台、租户、门店菜单分别由服务端按工作区返回；
- 需要重建角色管理页和权限矩阵；
- 需要补平台角色目录和租户自定义角色 API；
- 历史演示数据不迁移。
