# ADR 0022：租户工作区、上下文与门店数据范围

## Status / 状态

**proposed（提案中，2026-10-29）**。本 ADR 决定租户账号在总部/门店之间切换时的工作区、数据范围、权限来源与业务资源展示规则；不改变 ADR-0019/0020/0021 的 IAM 角色与权限边界。

## Context / 背景

租户账号通常同时拥有总部角色（如 `tenant.owner`）和门店角色（如 `store.manager`）。原实现存在以下问题：

1. `/select` 把同时拥有 `store.manager` 的租户管理员误判为“门店店长”，只展示门店入口；
2. 顶部上下文切换器把租户管理员固定为 TENANT 工作区，但直接进入 `/store` 或门店入口时会进入 STORE 工作区，形成“门店管理后台 + 租户角色”的混合状态；
3. 菜单只按权限过滤，没有按当前门店业态收敛；KTV/酒店店长能看到同一套通用门店菜单，餐厅/酒店专属入口缺失；
4. 上下文切换后只显示上下文名称，没有告诉用户当前是总部视角还是门店视角、数据范围是哪个门店、权限来自哪些角色；
5. 角色/权限页始终展示租户级角色模板，在门店上下文下容易被误读为“当前门店独占的资源”。

## Decision / 决策

### 1. 工作区与数据范围分离

```text
Workspace（工作区）：总部 / 门店 / 平台
Context（数据范围）：tenantId + organizationId + storeId
RoleBinding（角色来源）：总部角色 / 门店角色
Data Scope（资源范围）：当前上下文允许访问的数据
```

- **租户管理员**（拥有 `HEADQUARTERS` 工作区）：总部工作区，门店切换只改变数据范围，不切换成门店店长工作区；
- **门店店长**（只有 `STORE` 工作区）：门店工作区，只选当前授权门店，不展示总部入口和租户级权限管理；
- 平台运营：平台工作区，使用平台级上下文。

A 方案：租户管理员切门店保持 `租户管理后台`，顶部明确显示“总部视角 · 数据范围：门店 X”。

### 2. 工作区入口与路由守卫

- `/select` 对同时拥有总部/门店工作区的账号优先展示租户入口，不再因为 `store.manager` 绑定降级成门店入口；
- 租户账号直接访问 `/store` 时重定向回 `/admin/tenant/overview`；
- 门店店长复用 TENANT 业务页（如 KTV 配置）时，路由守卫先确保 STORE 上下文，保留门店 shell；
- 业务页面按 `businessType` 收敛：KTV 门店不能进入酒店页面，酒店门店不能进入 KTV 页面；后端读路径同样校验业态。

### 3. 顶部上下文条

所有后台页顶部显示：

```text
总部视角 · 数据范围：A380 KTV 旗舰店    授权角色：tenant.owner
门店视角 · 数据范围：SaaS Hotel          授权角色：store.manager
```

数据范围来自当前上下文，授权角色来自上下文候选（IAM 角色绑定）。用户能一眼区分“工作区”“数据范围”“角色来源”。

### 4. 菜单与业务资源

- 平台菜单由 AdminRole 控制，不按 IAM `required_permission` 隐藏；
- 租户/门店菜单由权限 + 业务类型剪枝；
- 新增门店业务菜单：酒店前台（HOTEL）、KTV 配置（KTV）；
- 门店店长只看到当前门店业态的菜单；租户管理员在门店上下文下也只看到匹配业态的租户菜单。

### 5. 角色/权限页在门店上下文下的表达

- 角色定义仍是租户级模板，门店只是数据范围；
- 角色页和租户权限矩阵在门店上下文显示提示：“当前数据范围：门店 X；角色模板为租户级定义”；
- 门店店长不能进入租户角色/权限页（路由守卫 + 后端权限 403）；
- 角色矩阵列头继续标注角色作用域（租户级/门店级）。

## Consequences / 后果

正向：

- 租户管理员切门店不再丢失总部工作区；
- 门店店长的入口、菜单、数据范围、权限来源一致；
- KTV/酒店菜单按业态正确展示；
- 权限页面不再把租户级模板伪装成门店独占资源。

代价：

- 租户管理员在门店上下文下仍拥有总部角色权限（符合 tenant.owner 语义），UI 需要明确标注“总部视角”；
- 业务专属页面需要持续维护 `businessType` 与门店权威数据校验；
- 门店店长的菜单需要按业态补齐。

## Alternatives considered / 备选方案

1. **切门店即进入门店工作区（模式 B）**：拒绝。租户管理员会丢失跨店管理能力，且与总部角色语义冲突。
2. **只靠菜单隐藏、不做路由/后端校验**：拒绝。直链/API 仍可跨业态访问。
3. **把门店角色权限合并进租户角色模板**：拒绝。角色定义与角色绑定必须分离。
4. **门店上下文下隐藏所有租户角色页**：拒绝。租户管理员仍需在门店数据范围下维护租户级角色模板，但必须有清晰提示。
