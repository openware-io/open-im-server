# 工程原则

[中文](03_ENGINEERING_PRINCIPLES.md) | [English](03_ENGINEERING_PRINCIPLES.en.md)

> 状态：`current`（`develop/2.3.0`）  
> 层级：L0 原则层  
> 作用：为 L1 领域标准和 L2 实践标准提供判断依据，不替代具体规范。

## 目标与适用范围

本规范定义 OpenChat 工程决策的**第一性原则**。当具体标准没有覆盖某个场景，或两个标准冲突时，用本规范判断取舍。

适用对象：

- 架构、开发、测试、交付、运维的日常决策；
- 新标准的制定与评审；
- 架构决策记录（ADR）和例外审批；
- 代码评审中“是否值得做”的争议。

不适用：

- 具体技术选型（由领域标准定义）；
- 具体目录、命名、日志字段（由实践标准定义）；
- 具体门禁实现（由 G 系列门禁定义）。

## 术语与前置假设

- **原则（principle）**：稳定的判断依据，不随工具变化。
- **标准（standard）**：在某个领域内可执行的约束。
- **实践（practice）**：标准在具体技术栈上的落地方式。
- **门禁（gate）**：对标准的自动化证据检查。
- **例外（exception）**：有边界、有负责人、有到期时间的临时偏离。

原则不是口号。每条原则必须能回答：

1. 它约束了什么决策？
2. 违反时会出现什么可观察后果？
3. 哪个标准或门禁在支撑它？

## 原则与约束

### P1 正确性优先于速度

- 正确性包括数据不丢、不重复、不越权、不误导。
- 不能以“先上线再修”为由跳过幂等、事务边界、权限校验。
- 紧急变更也必须有回滚路径和最小验证。

### P2 边界显式，所有权单一

- 每个服务、表、Topic、领域概念只有一个 Owner。
- 跨边界只通过 API、事件或明确契约；不共享表、不跨库 JOIN。
- 边界变化必须记录 ADR，不能靠口头约定。

### P3 单一事实源

- 每个事实只有一个权威来源；投影、缓存、索引都标明可重建。
- 文档、代码、迁移、配置冲突时，以可执行事实为准，并修正文档。
- 不允许同一规则在多个文档里各写一份。

### P4 自动化优先于人工记忆

- 能写成门禁的规则，不靠评审清单。
- 不能自动化的规则，必须有明确的检查人和证据。
- 门禁失败必须阻断，而不是只告警。

### P5 为失败而设计

- 默认网络、依赖、磁盘、进程都会失败。
- 关键链路必须有超时、重试、幂等、降级或死信。
- 变更必须可回滚；不可回滚的变更必须单独审批。

### P6 安全与隐私默认开启

- 最小权限、默认拒绝、敏感数据最小化。
- 密码、令牌、密钥、个人数据不得进入日志、MQ 明文或示例数据。
- 安全例外必须有到期时间和补偿控制。

### P7 可观测性默认具备

- 每个关键路径有日志、指标、追踪和关联标识。
- 告警必须对应可执行动作，不允许“只通知不处理”。
- 没有观测数据的服务不算可上线。

### P8 兼容性与可演进

- API、事件、配置、数据库变更必须考虑旧客户端和旧数据。
- 破坏性变更必须版本化，并提供迁移或弃用窗口。
- 不为了短期方便制造不可逆的契约。

### P9 简单优先，最小机制

- 能用简单方案解决，不引入新中间件、新抽象、新流程。
- 每个新增机制必须说明它替代了什么复杂度。
- 不为“未来可能需要”预建空框架。

### P10 文档是产品的一部分

- 使用者能否第一次成功，取决于文档而不是代码注释。
- 面向使用者的文档必须可发现、可复制、可验证。
- 文档变更和代码变更同等对待，必须过链接与一致性门禁。

## 模板或示例

决策记录模板：

```text
决策：是否允许服务 A 直接读取服务 B 的表？
原则：P2 边界显式 / P3 单一事实源
结论：不允许。
替代：B 提供 API 或发布事件；A 保存只读投影。
证据：契约测试 + 依赖方向门禁。
```

标准评审模板：

```text
标准名称：
层级：L0 / L1 / L2
领域：architecture / build / data / delivery / quality / security
支撑原则：P1–P10
对应门禁：Gxx
不覆盖的场景：
```

## 门禁与验证

- G48 标准目录：编号、英文摘要、索引完整性。
- G49 标准版图：每个标准必须映射到层级、领域、门禁和缺口。
- 具体领域门禁见 [门禁注册表](../governance/GATE_REGISTRY.md)。

## 可验证的验收标准

- 新标准能指出它支撑的原则；
- 原则冲突时有 ADR 或书面取舍；
- 标准版图没有孤立标准；
- 例外有负责人、到期时间和退出条件。
