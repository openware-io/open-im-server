# IM 三阶段可靠性改造计划

## 目标与门禁

改造分为三个阶段，任何阶段未通过本地工程校验、真实服务验证和 Android 真机验收，不进入下一阶段。

1. 登录设备历史与在线设备管理
2. 全局/私聊/群聊免打扰
3. 删除好友后保留聊天记录

每阶段必须保留兼容行为、补充回归测试、执行 `invoke-engineering-validation.ps1 -Scope Changed`，并用同一发布清单完成 Android 真机验收。真机验收使用既有设备基准和 `gv_chat_app/tools/release.ps1`，签名参数只从本机受控文件读取，不写入仓库、日志或构建产物清单。

## 阶段一：设备历史与在线状态

### 当前问题

`user_device_session` 以 `(user_id, device_id)` 唯一，同一设备重复登录会覆盖原记录；数据库 `active` 状态不能代表 WebSocket 实时在线；Token 未绑定具体 session，踢出设备无法保证旧 Token 立即失效。

### 目标方案

- 保留设备长期标识和登录历史；每次登录生成独立 `session_id`。
- Token/JWT 携带 `sessionId`、`deviceId` 和认证版本；请求与 WebSocket 鉴权检查会话状态。
- Redis 保存连接、心跳和网关实例；MySQL 保存登录历史、IP、登录方式和终态。
- 在线判定由连接建立、心跳、断开和超时共同驱动。
- 提供当前设备、单设备踢出、退出其他设备和全部设备退出。
- 设备列表区分 `ONLINE/OFFLINE/KICKED/LOGOUT`，并返回客户端版本与脱敏网络信息。

### 影响范围

用户服务登录/扫码/SSO、设备迁移、JWT 校验、WebSocket 网关、Redis、推送目标选择、Flutter 设备管理、桌面端设备标识、账号改密/注销和审计。

### 阶段门禁

- 单元/接口/数据库迁移测试通过；
- 本地 Kind 真实部署和设备接口验证通过；
- Android 真机完成多设备登录、在线/离线、踢出、退出其他设备、改密失效验证；
- 发布制品验签、版本接口和下载摘要核验通过。

## 阶段二：免打扰

统一全局、私聊、群聊和会话级策略。免打扰只影响通知弹窗、声音、震动和可配置角标，不影响消息落库、离线同步和聊天历史。服务端统一计算 WebSocket/JPush 行为，客户端只负责展示和本地同步。@提及、登录风控和安全通知按独立例外规则处理。

## 阶段三：删除好友后保留聊天记录

删除好友只改变关系和发送权限，不级联删除会话与消息。历史查询按会话成员和用户删除墓碑判断；会话保存对方资料快照；“删除好友”“隐藏会话”“删除我的消息”“清空聊天记录”分别建模；重新加好友复用稳定单聊会话，发送权限重新校验。

## 发布与回滚

每阶段使用独立版本和检查点记录，不跨阶段混合发布。失败时只回滚该阶段服务、客户端和迁移，保留既有数据；禁止恢复已下线的不安全入口。Android 正式包必须使用正式签名、`prod` 环境、`stable` 渠道和唯一递增 build number。
