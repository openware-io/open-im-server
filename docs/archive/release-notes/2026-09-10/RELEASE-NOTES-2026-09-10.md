## 一、功能改造（目标①②③④）

### ① 清空会话（删除服务器）后通知下发、对方端本地记录同步清除
| 项 | 内容 |
|---|---|
| 行为 | 聊天记录删除勾选「同时删除服务端」→ 服务端删除记录，**并联带删除对方记录**（对齐微信） |
| 服务端 | `clearPrivateChat` 删除双方消息+同步索引+已读+收藏+Mongo 热消息，并给**双方**写持久清空标记 + WS 通知对方；`clearGroupChat` 对**全体成员**各写标记 + 通知全员 |
| 接口 | `POST /api/v1/messages/clear-private`、`POST /api/v1/messages/clear-group` |
| 离线可靠 | `/messages/sync` 返回 `clearedConversations:[{conversationId,chatType,clearedAtEpochMs}]`，客户端据此删除本地早于该时刻的消息 |
| 真机/接口验证 | ✅ 私聊：标记双方各一条；A/B 的 sync 均返回清空标记；服务端消息与索引残留 **0**<br>✅ **群聊：3 人群清空后「全体成员」各一条标记，A/B/C 的 sync 均返回**（round 11）|
| 关键修复 | 实时 WS 通知在**对方离线时必然丢失**（`WsBroadcastService` 走 Redis 房间广播，无订阅者也返回成功），故补持久标记实现离线自愈 |

### ② per-user「删除仅我」tombstone（跨重装保留）
| 项 | 内容 |
|---|---|
| 行为 | 删除消息选「删除仅我」→ **只对本人生效**，不影响对方；**卸载重装后不复活** |
| 服务端 | 迁移 `V11__add_msg_user_deleted_message.sql`（唯一键 user_id+msg_id 幂等）；`POST /api/v1/messages/delete-for-me`；同步/历史/搜索/未读全部按墓碑过滤 |
| 客户端 | 统一走该接口；同步消费 `deletedMessages:[{msgId,conversationId,chatType}]` 清理本地副本并刷新会话预览 |
| 真机验证 | ✅ **卸载→重装→登录：消息列表「暂无消息」，被删消息未复活**（round 10，vivo）|
| 真机验证 | ✅ **另一台设备删除后重启本机：本地副本与会话预览均被清理**（round 14 发现缺口→修复→b5 截图确认）|
| 关键修复 | 「同步排除」只能阻止重新插入，**清不掉设备上已有的旧副本** → 补「带会话定位的墓碑下发」|

### ③ 密聊/密群同语义
| 项 | 内容 |
|---|---|
| 行为 | 密聊/密群同样支持「删除仅我」（只对本人生效）；「删除所有人」仍是**销毁密文并广播全群** |
| 接口 | `POST /api/v1/secret-messages/delete-for-me`、`POST /api/v1/secret-group-messages/delete-for-me` |
| 验证 | ✅ 接口级：端点已注册并正确鉴权（`Not a participant of this secret chat` / `Not a member of this secret group`，非 404）；普通 delete-for-me 无回归<br>⬜ 密聊完整 E2EE 端到端（建密聊→握手→密文→删除仅我→重装）**待跑** |

### ④ 端缓存 / Redis / Mongo / 同步索引 / 已读 / 收藏 三层一致
| 层 | 单条删除/撤回 | 会话清空 |
|---|---|---|
| 同步索引 | ✅ | ✅ |
| 已读状态 | ✅ | ✅ |
| 消息本体 | ✅ | ✅ |
| 收藏 | ✅ | ✅ |
| 媒体解绑 | ✅ | — |
| 未读投影 | ✅ | ✅ |
| **Mongo 热消息** | ✅（本次补） | ✅（本次补） |
| **验证** | ✅ Mongo 该会话热消息 **2 → 0**，总量 1839 → 1837（round 7）|
