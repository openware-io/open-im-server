# common-payment-channel-service

[中文](README.md) | [English](README.en.md)

> English summary; the Chinese document is normative.

## Responsibility

- Payment channel configuration and adapters.
- After a callback signature is verified, settle it against `common-payment-service`
  (`POST /internal/payment/channel-settlement`) using v2 internal HMAC headers generated by
  `InternalServiceSignature`. Only a settlement-accepted result yields a channel success ack; failures are
  logged and persisted as retryable state (`pay_channel_transaction.settlement_status/attempts/error`).
- A `sandbox` provider (local Kind E2E only, disabled by default) verifies callbacks with a fixed
  HMAC-SHA256 secret and drives the same settlement chain, so success/failure/duplicate/refund callbacks
  are testable without real merchant credentials. Shared/production manifests must not enable it.

## Boundary

- No business order state; orchestration belongs to the payment service.
