# 租户工作区与门店上下文（产品说明）

[English](TENANT_CONTEXT_MODEL.en.md)

> 状态：`current`（2026-10-29）
> 适用页面：租户后台顶部上下文切换、门店业务页、角色与权限页

## 1. 三个概念

| 概念 | 说明 |
| --- | --- |
| 工作区 | 总部后台 / 门店管理后台 / 平台后台，决定侧边栏与可用入口 |
| 数据范围 | 当前 `tenantId / organizationId / storeId`，决定页面查询的数据 |
| 角色来源 | 当前账号在该上下文下继承的总部角色与门店角色 |

角色定义属于租户，门店只决定角色绑定和数据范围。

## 2. 租户管理员

- 进入“租户管理后台”；
- 顶部上下文可切换到总部或任一下属门店；
- 切到门店后仍是**总部视角**，只是数据范围变为该门店；
- 页面顶部显示：`总部视角 · 数据范围：门店 X`；
- 菜单按当前门店业态收敛，例如 KTV 门店显示 KTV 配置，酒店门店显示酒店前台；
- 角色/权限页仍维护租户级角色模板，并提示当前门店数据范围。

## 3. 门店店长

- 进入“门店管理后台”；
- 只能看到自己被授权的门店，不显示总部入口；
- 顶部显示：`门店视角 · 数据范围：当前门店`；
- 菜单只包含当前门店业态的业务入口（酒店/KTV/通用门店）；
- 不能进入租户角色/权限页；
- 直接访问酒店/KTV 跨业态页面会被重定向。

## 4. 业务菜单

门店和租户菜单按 `business_type` 过滤：

- 酒店门店/酒店上下文：显示酒店前台、房型房价等；
- KTV 门店/KTV 上下文：显示 KTV 配置；
- 通用门店菜单（预约、收银、订单、资源、库存、会员、报表、门店设置）保留。

后端读路径同样校验门店业态，避免绕过菜单直连 API 读取其他业态数据。

## 5. 权限来源展示

顶部上下文条展示 `授权角色`：

```text
总部视角 · 数据范围：A380 KTV 旗舰店    授权角色：tenant.owner
门店视角 · 数据范围：SaaS Hotel          授权角色：store.manager
```

角色/权限页在门店数据范围下显示“角色定义为租户级模板”的提示，避免把租户级权限资源误认为当前门店独占。

## 6. 验收标准

- 租户管理员 `/select` 只出现租户后台入口；
- 租户管理员直接访问 `/store` 会回到租户经营总览；
- 租户管理员切门店后仍是租户管理后台，顶部显示总部视角与门店数据范围；
- 门店店长只看到当前门店，不能进入租户角色/权限页；
- KTV 店长菜单只有 KTV 业务，酒店店长菜单只有酒店业务；
- KTV 门店直连酒店房态接口返回业态不匹配；酒店门店直连 KTV 接口被拒绝；
- 顶部授权角色与上下文候选角色一致。
