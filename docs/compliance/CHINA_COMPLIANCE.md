## 1. 文档目的与边界

本文件依据中国现行法律法规，对当前 IM 系统的合规合法问题进行盘点，形成「问题清单」与「治理方案」。

- 范围：仅中国境内运营、面向中国用户（含 KTV/酒店/足浴等 SaaS 商户及其终端用户）的合规要求。
- 非目标：不覆盖出海/跨境运营（另立文档）；不替代正式法律意见，重大事项须由法务与持证机构出具结论。
- 状态说明：清单中的「现状」基于工程仓库可查证据标注；标注「待确认」的项需运营方提供资质与制度文件核实。

#### 4.3.1 E2EE 合规专项（重点）

E2EE（私密聊天）使平台无法对内容履行审核义务，是 IM 系统在境内合规的核心矛盾点。治理原则：

1. 默认明文、可选加密：普通聊天保持服务端可审核（明文存储 + 加密落盘），E2EE 仅作为用户主动选择的私密聊天，默认关闭。
2. 风险告知 + 单独同意：用户启用 E2EE 前明示平台无法审核该会话内容、涉违法须自负责任，取得单独同意。
3. 可配合监管的技术预留：在合规允许的前提下，保留密钥托管/恢复/审计能力（如企业场景托管密钥、法院令状下提供解密），避免完全不可监管的黑盒。
4. 范围限制：E2EE 限一对一私密会话，不开放群聊 E2EE（群聊必须可审核）。
5. 商用密码合规：评估 X25519 + AES-GCM 与商用密码管理条例的兼容性，必要时切换国产 SM2/SM3/SM4 或完成合规评估。

## 5. 治理方案

### 5.1 治理框架与责任分工

| 角色 | 职责 |
| --- | --- |
| 法务/合规负责人 | 资质办理、法律意见、制度签发、监管对接 |
| 安全负责人 | 等保、加密落地、日志留存、应急响应 |
| 产品负责人 | 隐私政策、实名、青少年模式、举报入口、E2EE 产品边界 |
| 研发负责人 | 技术落地（内容审核链路、数据加密、日志、审计） |

### 5.2 优先级与路线图

#### P0 —— 法律红线（立即启动，1-2 月内闭环）

1. 资质：ICP 备案/许可证、EDI（如适用）、App 备案、等保定级备案。
2. 实名制：强制实名注册 + 账号信息审核。
3. 内容审核：明文聊天全量审核链路（敏感词 + 图片/音视频 AI + 人工复审）+ 违法信息处置/上报 + 举报入口。
4. E2EE 合规：落地 4.3.1 治理原则（默认明文、可选加密、单独同意、范围限制、可配合监管）。
5. 隐私政策 + 单独同意：发布隐私政策，敏感信息/第三方 SDK/未成年人单独同意。
6. 敏感数据加密：落地 SENSITIVE_DATA_PROTECTION.md Phase1/2（正文 + PII 应用层加密 + KMS）。

#### P1 —— 重点合规（2-4 月）

7. 数据分类分级 + 数据资产清单。
8. 个人信息保护负责人 + PIA + 泄露应急（72h）。
9. 日志留存不少于 6 个月 + 通信内容记录策略 + 日志脱敏。
10. 未成年人保护（青少年模式、未成年人同意）。
11. 反诈（涉诈监测、账号处置）。
12. 支付合规（牌照/预付卡/反洗钱）。

#### P2 —— 持续完善（季度）

13. 商用密码合规评估（SM2/SM3/SM4）。
14. 数据出境/重要数据（按需评估）。
15. 合规审计（个人信息保护合规审计、等保年度测评）。
16. 制度文档化：内容审核制度、投诉处置制度、应急预案、数据删除规范。

### 5.4 验收指标

| 维度 | 验收标准 |
| --- | --- |
| 资质 | ICP/EDI/App/等保备案材料齐备 |
| 实名 | 新用户 100% 实名后才可发布信息 |
| 内容审核 | 明文内容 100% 过审；违规内容 24h 内处置 |
| 加密 | 消息正文/PII 不以明文落库/缓存/MQ/日志/备份 |
| 日志 | 网络日志留存不少于 6 个月；日志无敏感明文 |
| 隐私 | 隐私政策覆盖全部场景；注销/删除/导出可用 |
| 应急 | 安全事件 72h 上报预案演练通过 |
